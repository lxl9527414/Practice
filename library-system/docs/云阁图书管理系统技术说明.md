## 5. 核心业务流程

### 登录流程

```text
前端提交用户名和密码
    ↓
后端使用 BCrypt 校验密码
    ↓
生成随机 Token
    ↓
将用户信息写入 Redis
    ↓
返回 Token 给前端
```

### 权限校验流程

```text
请求携带 Authorization: Bearer Token
    ↓
AuthInterceptor 从 Redis 查询用户
    ↓
检查 @RequireRole 注解
    ↓
角色匹配则放行
    ↓
Controller 执行业务
```

### 借书流程

```text
检查图书库存
    ↓
条件更新库存：
UPDATE book
SET available_stock = available_stock - 1
WHERE id = ? AND available_stock > 0
    ↓
更新失败则回滚
    ↓
插入 borrow_record
```

### 还书流程

```text
查询借阅记录
    ↓
检查记录状态为 BORROWED
    ↓
记录状态改为 RETURNED
    ↓
设置归还时间
    ↓
恢复图书库存
```

## 6.1 预约状态流转

```text
读者预约（库存为 0）
    ↓
WAITING 排队中 ──取消──> CANCELED
    ↓ 图书归还，队首提升
READY 待取书 ──取书借阅──> COMPLETED
    ↓ 超过保留期（定时任务每小时检查）
EXPIRED 已失效 ──> 自动提升下一位读者
```

同一读者对同一本书只允许存在一条排队中 / 待取书的记录，由 `book_reservation.active_key` 生成列上的唯一索引兜底。

## 7. 关键设计点

### Token 存储

当前使用不透明随机 Token，而不是 JWT。

```text
key：library:token:<随机值>
value：UserSession JSON
TTL：604800 秒，即 7 天
```

优点：

- 退出登录时可以直接删除 Redis key
- 服务端可以控制登录状态

### 库存并发控制

使用 MySQL 条件更新，而不是先查询再修改：

```sql
UPDATE book
SET available_stock = available_stock - 1
WHERE id = ?
  AND available_stock > 0
```

这样可以避免并发借书时出现库存超卖。

### 密码安全

数据库只保存 BCrypt 加密后的密码哈希，不保存明文密码。

### 借阅规则统一配置

借阅上限、借期、续借次数、每日罚金、罚金上限、预约上限和到书保留时长集中存放在 `borrow_rule` 单行配置表，`BorrowRuleService.current()` 统一读取，避免规则散落在业务代码里。

### 逾期罚金计算

归还时按 `due_at` 与当前时间的天数差向上取整，乘以每日罚金，并用 `fine_max` 封顶：

```text
罚金 = min(逾期天数 × 每日罚金, 罚金上限)
```

罚金状态在借阅记录上流转：`NONE`（无罚金）→ `UNPAID`（待缴纳）→ `PAID`（已缴纳，管理员操作）。

### 预约队列与库存联动

- 库存为 0 时才允许预约，队列按 `created_at`、`id` 排序保证先到先得
- 归还时调用 `promoteNext()` 把队首提升为 `READY`，并写入保留截止时间
- 待取书期间其他读者不能借走该书；保留超时由 `LibraryScheduledTask` 每小时释放并顺延
- 已有预约的图书不允许续借，避免读者长期占用

### 操作日志切面

`@Auditable(module, action)` 注解 + Spring AOP 在方法执行前后记录：操作人、模块、动作、请求参数（密码字段自动脱敏）、IP、结果、错误信息和耗时。日志保留 90 天，由定时任务每天凌晨清理。

### 持久层：MyBatis-Plus 与 Mapper XML 的分工

Mapper 接口仍然是一张表一个，但 SQL 不再全部手写：

| 场景 | 实现位置 | 示例 |
| --- | --- | --- |
| 单表增删改查 | `BaseMapper<T>` 内置方法 | `userMapper.insert(user)` |
| 单表条件查询 / 分页 | Service 中的 `LambdaQueryWrapper` | 图书关键词、分类筛选 |
| 跨表或动态 SQL | Mapper XML | `BorrowRecordMapper.xml` 关联 `sys_user` 查询借阅记录 |

因此 `BookMapper.java`、`UserMapper.java` 只有一行继承 `BaseMapper`，没有对应 XML；只有借阅记录分页这类多表动态查询才需要写 XML。用原生 MyBatis 的学习项目每张表都手写 SQL，所以 XML 文件看起来更多。
